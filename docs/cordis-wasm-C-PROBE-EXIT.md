# wasm 桥两点式探针（C）评估报告与出口

**依据**：计划 `docs/cordis-wasm-C-PROBE-PLAN.md`；C1（REVIEW-C1）/C2（REVIEW-C2）闭环。
**判定日期**：2026-08-20（C1/C2 实跑 + C3 评估）。
**探针目标**：用两阶段 guest（零 core 改动）回答——「guest 必须以远端结果为输入继续」是不是真实刚需且值得动 core（B）？

---

## 1. 探针做了什么（可实现性）

- C1：宿主回填 → `ctx.set_dyn` 回注核心 store（echo(7)→14 ✓）。
- C2：两阶段全链路——阶段 1 激活（db + submit）→ worker 回填 → `preseed_mirror` 回注镜像 → revision bump 阶段 2 读回继续（`probe_out=15` ✓）+ 失败兜 `probe_err` ✓ + 退役静止 ✓。
- **零 core 改动**（护栏：C 全链不触 crates/cordis-core）。

## 2. 评估（作者体验 × 真实插件形态对照）

两阶段 = 「提交并完成 → 宿主把结果回注 → 再激活消费」。对照真实形态（如"调宿主 LLM → 拿回复 → 生成下一条"）：

| 维度 | 体验 | 判定 |
|---|---|---|
| **一次性消费（刚好 C2 的形态）** | 两步分支 + preseed + rev bump——一次往返**可用且不算别扭**（guest 分支读镜像、状态经输入传递） | 🟡 可作捷径 |
| **多次往返 / 持续 agent** | 每次往返都要"回注 + rev bump + 分支重扫"；状态需显式落键、跨激活传递 | 🔴 明显反直觉/笨重 |
| **真正远端失败**（worker Err） | `preseed_mirror` 只存 `Value` 成功形态——**worker 失败无通道达镜像**（REVIEW-C2 M-1：探针只模拟"载荷形态不合法"，不覆盖"远端操作失败"） | 🔴 缺错误通道 |
| **生命周期** | preseed 无逆、unload 不清、值跨卸载存活（REVIEW-C2 M-2：隐含契约，探针内可接受） | 🟡 正式化须定 |

## 3. 结论与建议

**guest-await 需求强度**：
- 一次性、成功主路径的"请求-消费"——两阶段（C）**够用且直观**；
- 持续 agent / 多次往返 / 远端真实失败——两阶段（C）**明显不够**：状态显式化 + rev bump 编排 + 无错误通道，作者写起来绕、且一遇远端失败就断链。

**建议**（结合 `docs/cordis-core-AWAIT-PROPOSAL.md`）：
- **倾向于授权 B（core 步进扩展 Await）**——C 暴露的 ①②③（多次往返编排、真失败无通道、状态显式化）在真实 agent 插件形态中都会出现；B 给完整 take-await 语义 + 统一错误通道 + 免显式状态编排，且通用（其它同步桥同受益）。
- **C 保留为轻量捷径**：一次性"请求-消费"场景可继续用（preseed 形态，文档标注探针/轻量路径）。
- B 开工前按 B 提案 §5 决策点确认（含 core 改动授权 + THEORY-MAP 偏离标注）。

## 3bis. B 落地后的定位（2026-08-20 增补）

- **take 完整语义已由 B A2a 打通**（core `Step::Await` + `Runtime::advance` + wasm 桥接线，`a2_e2e` 直证）——C 探针验证过的"请求-消费"两阶段形态不再需要 preseed 分支（c2 测试已移除）。
- **C 定位调整为轻量捷径/探针归档**：一次性"请求-消费"场景可继续用「single submit + 宿主回填」形态（preseed_mirror 保留为宿主输入面工具；正式 take-await 见 B A2a）。

## 4. 出口

**C 探针完成**：两阶段可行（零 core 改动验证"两阶段模拟 await"）+ 评估如实记录（三次往返/真失败/生命周期 X 点）+ 建议授权 B。→ 流转：用户按本报告 + B 提案决策（授权 B / 降级待办 / 再议）。
