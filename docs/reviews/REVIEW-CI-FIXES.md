## CI-FIXES-3（2026-08-22）：build wasm guest (Go) wit-bindgen not found 修复（c0d3e8e）

- **审查对象**：`c0d3e8e`（fix(ci)：build wasm guest (Go) 失败修复——CI 缺装 wit-bindgen-cli（pin 0.60.0 与生成代码一致）+ build.sh PATH 检查（REVIEW-P4 nit 落地）+ README 前置说明）
- **审查人**：追溯审查员（CI-hotfix 提交须至少追溯审查——本轮独立只读核查，不改代码）

### 现象

GitHub CI 步骤 **build wasm guest (Go)** 失败：`examples/wasm-plugin-go/build.sh:21: wit-bindgen: command not found`（exit 127）。
（build.sh 第 0 步 `wit-bindgen go --out-dir .` 重生成 go 绑定需要；缺装时无上下文裸报 `command not found`。）

### 根因

`ci.yml` 的 `check` job 装了 Go toolchain（`setup-go`）但**未装 wit-bindgen-cli**；而 build.sh 第 0 步要调用它。仓库内生成代码头注为 `// Generated by \`wit-bindgen\` 0.60.0. DO NOT EDIT!`——即仓库绑定的生成器版本为 0.60.0，CI 环境却缺失该二进制。此外 build.sh 无 PATH 前置检查（缺失时只报裸 `command not found`，无可操作指引），README 构建节也未列前置。

### 修复（c0d3e8e，三文件）

1. **`.github/workflows/ci.yml`**：新增 `Install wit-bindgen-cli` 步骤，`cargo install wit-bindgen-cli --version 0.60.0`（pin 与仓库生成代码版本一致）。置于 job `check` 的 `steps` 列表内（index 3），6 空格缩进、与相邻 `- name:` 步骤一致——YAML 语法核对通过（ruby YAML 解析 OK；原始行 `      - name: ...` / `        run: ...` 缩进与 `Cache cargo artifacts` 等邻居对齐，已在 steps 列表内）。
2. **`examples/wasm-plugin-go/build.sh`**：新增 PATH 检查——`if ! command -v wit-bindgen >/dev/null 2>&1; then` 缺失时打印可操作错误 + 安装命令、`exit 127`（**落地原 REVIEW-P4 nit**："wit-bindgen PATH 检查可选"）。
   - **位置**：置于 `cd "$(dirname "$0")"` / `ROOT=...` 之后——`command -v` 不依赖 cwd/ROOT，位置对正确性无影响（放前后皆可）。
   - **`set -euo pipefail` 安全性**：该命令处于 `if` 条件且前置 `!` 取反，errexit 对**整个条件**抑制（不触发 set -e）。实测 `bash -c 'set -euo pipefail; if ! command -v <missing> ...; then ...; fi; ...'`：缺失分支正常进入、脚本不因该检查误退；存在分支正确走 else。
3. **`examples/wasm-plugin-go/README.md`**：构建节补前置说明——`go`（>= 1.24）、`wit-bindgen-cli 0.60.0`（`cargo install wit-bindgen-cli --version 0.60.0`，build.sh 第 0 步重生成 go 绑定需要；缺失时 build.sh 报错并给出安装命令）。
